# RetroLot: онлайн-аукціон вінтажних речей

Курсовий проєкт з дисципліни «Веб-технології та веб-дизайн». Тема: група 1, № 4, рівень високий.
Лоти з обмеженим часом торгів; ставка приймається, лише якщо перевищує поточну найвищу щонайменше на мінімальний крок.

## Стек
- Node.js 24, Express 5 (HTTP API), `node:sqlite` (SQLite у режимі WAL), Nodemailer (email-сповіщення)
- Клієнт: HTML + CSS + JavaScript без фреймворку (SPA на History API), UA/EN
- Тести: вбудований `node:test`; CI: GitHub Actions; контейнер: Docker / Docker Compose

## Запуск
```bash
npm ci
npm run seed      # створює БД з нуля: схема з migrations/ + 200 лотів, 50 користувачів, 1500 ставок
npm start         # http://localhost:3000
npm test          # модульні, конкурентний і наскрізний тести
```
Або одною командою в контейнері: `docker compose up --build`.

Демо-акаунти (лише для локальної розробки): `admin@retrolot.test` / `admin12345`,
`user1@retrolot.test` ... `user48@retrolot.test` / `password123` (user1-15 продавці), `blocked@retrolot.test` заблокований.

Додати адміністраторів (людина спершу реєструється на сайті): `npm run make-admin -- a@mail.com b@mail.com`,
зняти права: `npm run make-admin -- a@mail.com --remove`.

Змінні оточення описані в `.env.example` (SMTP, Google OAuth, термін оплати).

## Ролі
| Роль | Може |
|---|---|
| Гість | каталог із пошуком, фільтром за категорією й ціною, сортуванням; сторінка лота з історією ставок |
| Учасник торгів | ставка з перевіркою кроку, автоставка до межі, список спостереження, сповіщення про перебиття (на сайті й email), історія ставок, оплата виграного лота |
| Продавець | створення лота (опис, мін. 3 фото, стартова ціна, час), редагування й зняття лише до першої ставки, перегляд переможця і його контактів після оплати |
| Адміністратор | модерація лотів, скасування торгів з порушенням, блокування й розблокування учасників, дані продавця |

## Конкурентна операція: ставка
`bids/service.js`. Перевірка й запис ставки виконуються **одним** `UPDATE lots ... WHERE amount >= current_price + min_step AND <торги відкриті>`.
Нуль змінених рядків означає, що вас випередили. Тест `test/bids.test.js` запускає 8 окремих процесів, які
одночасно ставлять однакову суму: приймається рівно одна ставка. Повторний запит з тим самим `Idempotency-Key` не створює дубля.
Історія ставок незмінна (тригери забороняють UPDATE/DELETE). Деталі в `docs/adr/0001-*.md`.

## Завершення торгів і оплата
Фоновий процес (`server.js`, кожні 5 с) закриває лоти за часом, навіть якщо сторінку ніхто не відкрив,
створює платіж для переможця й шле листи. Якщо переможець не оплатив за `PAY_WINDOW_HOURS`, його акаунт блокується,
а лот пропонується наступному учаснику за його найвищою ставкою. Оплата імітується: номер картки перевіряється (Луна) і не зберігається, лише останні 4 цифри.

## Структура (за функціональними областями)
```
auth/           реєстрація, вхід, Google OAuth, сесії (Argon2id)
lots/           каталог, сторінка лота, створення/редагування, фото, спостереження
bids/           ставки й автоставки
payments/       завершення торгів, оплата, прострочення
admin/          модерація, скасування, блокування
notifications/  сповіщення і розсилка email
lib/            валідація, помилки, HTTP-шар (problem+json, request id, JSON-логи)
migrations/     SQL-міграції
public/         клієнт (index.html, app.js, i18n.js, style.css)
test/           тести
docs/           ADR, коди помилок, план запиту до/після індексу
openapi.yaml    специфікація API (OpenAPI 3.1)
```
Пояснення до кожного файлу коду українською: [docs/code/README.md](docs/code/README.md).

Кожна область має `service.js` (бізнес-логіка й доступ до даних, без HTTP, викликається з тестів напряму) і `routes.js` (HTTP).

## Спостережуваність
- JSON-логи з рівнями (`LOG_LEVEL`), без cookie та заголовків авторизації
- `X-Request-Id` у кожній відповіді й у тілі помилки
- `GET /api/health`

## Резервне копіювання
```bash
sqlite3 data/auction.db ".backup data/backup.db"     # гаряча копія
cp data/backup.db data/auction.db                     # відновлення (сервер зупинено)
```
Фото лежать у `data/uploads/`, їх копіюють разом з БД.

## Обмеження
- Немає розгортання з HTTPS і власним доменом
- TypeScript і генерація типів клієнта з OpenAPI: клієнт на чистому JS, типи не генеруються
- ESLint/Prettier: `npm run lint` лише перевіряє синтаксис
