# migrations/002_lots_status_index.sql

Додає індекс `lots_status_ends` на `(status, ends_at)`.

## Навіщо
Головна сторінка шукає активні лоти й сортує їх за часом завершення. Без індексу SQLite перебирає всі лоти і сортує їх у тимчасовій структурі. З індексом одразу йде до активних лотів у потрібному порядку і зупиняється після 20 штук.

Вимірювання на 200 лотах (докладно в `docs/query-plan.md`):
| | План | Час |
|---|---|---|
| без індексу | `SCAN l` + `USE TEMP B-TREE FOR ORDER BY` | 42,2 мкс |
| з індексом | `SEARCH l USING COVERING INDEX lots_status_ends` | 17,8 мкс |

## Чому окрема міграція
Методичка (5.5) вимагає показати план запиту до і після додавання індексу. Окремий файл робить цю різницю наочною.
