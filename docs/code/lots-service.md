# lots/service.js

Усе про лоти: каталог, історія, сторінка лота, створення, редагування, зняття, спостереження.

## Функції
- **`list(query)`**: каталог на головній. Показує лише схвалені лоти, які ще не закінчились.
  - фільтри: пошук у назві й описі (`q`), категорія, тег, ціна від/до, стан (йдуть / ще не почались);
  - сортування: скоро кінець, скоро старт, нові, ціна ↑/↓;
  - **все рахується в SQL**, а не в браузері (методичка 5.3);
  - у пошуку символи `%` і `_` екрануються, щоб користувач не міг підсунути свій шаблон.
- **`paged(sql, params, page, size)`**: пагінація зі зміщенням: `COUNT(*)` для загальної кількості, `LIMIT/OFFSET` для сторінки. Чому зміщення, а не курсор: `docs/adr/0003-offset-pagination.md`.
- **`history(userId, query)`**: «Історія»: куплені, продані, де я ставив. Для кожного лота рахує `relation` (bought / sold / bid) і статус оплати.
- **`get(lotId, viewer)`**: дані сторінки лота. Важливо:
  - лот на модерації, відхилений чи знятий бачать лише продавець і адмін, решта отримують **ту саму помилку, що й для неіснуючого** (`not_found`);
  - додає фото, теги, історію ставок, мінімальну ставку, чи стежить користувач, його автоставку, його платіж;
  - продавець і адмін бачать переможця; контакти покупця лише **після оплати**;
  - адмін бачить дані продавця.
- **`create(userId, input)`**: новий лот.
  - перевіряє поля, щонайменше 3 фото, картку продавця (Луна);
  - час: старт не в минулому, тривалість від 10 хв до 30 днів, крок не більший за стартову ціну;
  - зберігає дані продавця і робить роль `seller`;
  - лот отримує статус `pending` (чекає модерації).
- **`update(userId, lotId, input)`**: редагування. Умова «немає ставок» записана **прямо в UPDATE** (`bid_count = 0`): якщо в ту саму мить хтось поставив, редагування відхиляється. Після редагування лот знову йде на модерацію.
- **`withdraw`**: зняти з торгів, теж лише без ставок.
- **`mine`**: «Мої лоти» продавця.
- **`watch` / `watchlist`**: список спостереження (багато-до-багатьох `watchlist`).
- **`categories` / `tags`**: довідники.

## Пояснення рішень
- **Чому редагування лише до першої ставки і як це гарантовано?** Вимога ТЗ; гарантує умова `bid_count = 0` в самому `UPDATE`.
- **Як захищено чужі лоти?** Спершу перевіряється `seller_id`; для чужого лота відповідь `not_found`.
