# lib/errors.js

Маленький файл: клас `DomainError` і функція `fail`.

## Що всередині
- **`DomainError(code, detail, extra)`**: помилка бізнес-логіки.
  - `code`: короткий код (`bid_too_low`, `not_found`...);
  - `detail`: текст для людини;
  - `extra`: додаткові дані (наприклад, `min_bid`).
- **`fail(code, detail, extra)`**: створює і одразу кидає таку помилку. Пишеться в один рядок: `if (!lot) fail('not_found', 'Lot not found')`.

## Навіщо окремий клас
Сервіси не знають про HTTP. Вони кажуть, *що* сталося (`bid_too_low`), а `lib/http.js` вирішує, *як* відповісти (409). Так сервіс можна перевіряти в тесті без сервера: `assert.throws(..., { code: 'bid_too_low' })`.

## Пояснення рішень
- **Як бізнес-логіка відділена від HTTP?** Через цей клас: сервіси кидають `DomainError`, а статус обирає HTTP-шар.
