# db.js

Відкриває базу SQLite, вмикає потрібні режими, застосовує міграції і дає функцію транзакції `tx`.

## Що робить
1. Файл бази: `DB_FILE` з `.env` або `data/auction.db`. Папка `data/` створюється сама.
2. Режими SQLite:
   - `journal_mode = WAL`: читання не блокуються записом;
   - `foreign_keys = ON`: база перевіряє зв'язки між таблицями;
   - `busy_timeout = 5000`: якщо база зайнята іншим записом, чекати до 5 с, а не падати.
3. **`tx(fn)`**: виконує `fn` у транзакції.
   - `BEGIN IMMEDIATE` одразу бере блокування на запис. Два записи, навіть з різних процесів, ідуть строго по черзі.
   - Помилка всередині: `ROLLBACK`, нічого не збережеться частково.
   - Якщо транзакція вже відкрита, просто виконує `fn` (вкладені виклики не ламаються).
4. **`migrate()`**: читає `migrations/*.sql` по порядку назв. Номер останньої застосованої міграції зберігається в `PRAGMA user_version`, тож кожна застосовується рівно один раз.

## Пояснення рішень
- **Чому SQLite, а не PostgreSQL?** Методичка дозволяє обґрунтовану альтернативу; обґрунтування в `docs/adr/0002-sqlite-instead-of-postgresql.md`.
- **Як відтворити схему з нуля однією командою?** `npm run seed`: видаляє файл бази, `db.js` створює її заново міграціями, сід наповнює даними.
- **Що таке транзакція?** Група змін, яка зберігається повністю або не зберігається зовсім.
