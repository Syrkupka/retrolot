# server.js

Точка входу. Збирає застосунок Express і запускає фоновий таймер.

## Що робить
1. **`createApp()`** будує застосунок, порядок має значення:
   - `requestContext`: дає кожному запиту id (`X-Request-Id`) і пише JSON-лог;
   - заголовки безпеки: `Content-Security-Policy` (скрипти лише з нашого сайту), `X-Content-Type-Options`, `Referrer-Policy`;
   - розбір JSON: для `/api/lots` ліміт 25 МБ (там фото), для решти 100 КБ;
   - `loadUser`: знаходить користувача за cookie `sid`;
   - `/api/health` (сервер і база живі) і `/api/config` (чи увімкнено Google, email підтримки);
   - маршрути з `auth/`, `admin/`, `lots/`, `payments/`;
   - невідомий `/api/...` віддає 404 у форматі problem+json;
   - статика: `/uploads` (фото користувачів) і `public/` (сайт);
   - будь-яка інша адреса отримує `index.html`, бо сторінки малює клієнт (SPA);
   - `errorHandler` останнім: перетворює помилки на відповіді.
2. **`startJobs()`** кожні 5 секунд: закриває лоти, час яких вийшов (`closeEnded`), прострочує неоплачені платежі (`expireUnpaid`), розсилає листи (`sendPending`). Прапорець `busy` не дає запустити новий цикл, поки попередній не скінчився.
3. Якщо файл запущено напряму (`node server.js`), слухає порт з `PORT` (за замовчуванням 3000).

`createApp` експортується окремо, щоб тест `e2e.test.js` міг підняти сервер без таймера.

## Пояснення рішень
- **Чому завершення торгів у таймері, а не при відкритті сторінки?** Вимога ТЗ: лот має завершитися, навіть якщо на нього ніхто не дивиться.
- **Навіщо `/api/health`?** Методичка (5.7) вимагає ендпоїнт перевірки працездатності; його також використовує `HEALTHCHECK` у Dockerfile.
