# payments/service.js

Що відбувається після торгів: хто переможець, оплата, що буде, якщо не оплатив.

## Функції
- **`closeEnded(now)`**: закриває всі лоти, час яких вийшов. Викликається таймером кожні 5 с (`server.js`), тож лот закінчується, навіть якщо його сторінку ніхто не відкрив.
  - `UPDATE ... SET status = 'ended' WHERE status = 'active'`: якщо інший процес уже закрив лот, змінено 0 рядків, і повторно нічого не робиться;
  - далі `offerToNext`.
- **`offerToNext(lot, now)`**: шукає учасника з найвищою ставкою, який **не заблокований** і **ще не мав платежу** за цей лот. Він отримує платіж за **своєю власною** найвищою ставкою. Якщо таких немає, лот лишається без переможця, продавець отримує сповіщення.
  - Звичайно це лідер торгів. Якщо лідера заблокували до кінця торгів, лот одразу йде наступному.
- **`openPayment`**: створює платіж з терміном `PAY_WINDOW_HOURS` (48 год), записує переможця в лот, надсилає сповіщення «ви виграли».
- **`expireUnpaid(now)`**: платежі, термін яких минув:
  1. платіж стає `expired`;
  2. покупця **блокують** (`block_reason = 'unpaid'`);
  3. `offerToNext` пропонує лот наступному учаснику.
- **`pay(userId, paymentId, input)`**: демо-оплата.
  - перевіряє дані покупця і картку: Луна, термін дії `ММ/РР` у майбутньому, CVV 3-4 цифри;
  - повний номер і CVV **не зберігаються**, лише останні 4 цифри для чека;
  - `UPDATE ... WHERE status = 'pending' AND due_at > now`: оплатити можна лише вчасно і лише один раз;
  - повторне надсилання вже оплаченого повертає той самий результат без другого списання;
  - сповіщення: покупцю чек, продавцю «оплачено».
- **`get`**: платіж для сторінки оплати; чужий платіж дає `not_found`.

## Пояснення рішень
- **Що буде, якщо переможець поставив мільярд і не заплатив?** Одна ставка обмежена 10× мінімальної (див. `bids-service.md`). Якщо все одно не оплатив: блокування і лот іде наступному учаснику за його ставкою.
- **Гроші справді списуються?** Ні, оплата імітується. Справжня потребувала б платіжного сервісу (LiqPay, Stripe).
